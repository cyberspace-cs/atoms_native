# Core loop reliability implementation plan

**Goal:** 修复精修假成功、上下文丢失、评审默认放行与离线门禁误调用真实模型。

**Architecture:** 保留 FastAPI / SQLite / 原生 JS 与 generator 事件接口。流水线产生明确结果；独立版本提交服务只提交可交付结果，并以事务校验父版本。统一 Python 门禁在临时目录运行，强制离线。

**Tech Stack:** Python, unittest, FastAPI TestClient, SQLite, Playwright, GitHub Actions.

**Spec:** 用户于 2026-09-04 明确确认上一轮诊断提出的核心定向重构范围并授权 SSH 推送 Gitee。

## Global constraints

- 真实模型 API 调用预算为 0；不执行真实评估、策展或线上部署。
- 保留分享、Remix、沙箱、持久化和管理员限定 Race。
- 保留既有未跟踪文件；只提交本轮改动。
- 初次生成允许明确标注的离线产物；精修无改动/失败不创建新版本、不切换当前版本。
- 真实调用设单轮硬上限；格式修正最多一次，修复最多一轮并复审。

### Task 1: 流水线结果与调用控制

Files: `tests/test_core_loop.py`, `server/agent/pipeline.py`, `server/agent/llm.py`.

Interface: `run_pipeline(...)` 返回现有字段及 `status`（success/degraded/failed/unchanged）、`error`、`call_count`。

- [ ] RED：伪造外部 chat 响应，验证重试保留原上下文、非法精修失败、无效评审不放行、修复复审、供应商失败立即停止、调用上限、offline 即使配有 key 也不请求网络。
- [ ] GREEN：在调用边界检查预算，失败抛出内部受控异常并转成结果；格式重试使用 `user_prompt + HTML_ONLY_RETRY`；严格校验评审 JSON。
- [ ] Verify: `python -m unittest discover -s tests -p test_core_loop.py -v`。

### Task 2: SSE 与版本提交闭环

Files: `server/generation_service.py`, `server/database.py`, `server/main.py`, `public/app.js`, `tests/test_core_loop.py`.

Interface: `commit_generation(project, result, message=None)` 事务提交并返回版本 ID；结果不可提交或父指针已改变则不写版本。

- [ ] RED：TestClient 真实请求验证失败不新增版本、不改变指针、成功仅保存一次、版本保存 mock/状态/父版本/调用数、并发冲突不覆盖、异常发 error 不发 done。
- [ ] GREEN：共享 SSE 服务适配与事务保存；前端消费终态，流意外结束明确报错。
- [ ] Verify: 核心回归 + 原有 unit_tests / frontend_checks / regression_guard。
