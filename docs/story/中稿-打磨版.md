# 面试官让我 48 小时做个 Atoms，我给 AI 招了四个员工
> Atoms Native 中稿 · 打磨版 v2（按 rubric 逐项改进：before/after 前置、术语段落去说明书化、补互动落点）

---

先说结果：我备忘录里躺着 7 个死掉的点子。做完这个项目的那个晚上，第 8 个活了。

给我妈做的吃药提醒，帮朋友工作室排班的表，一个「今晚谁洗碗」的转盘。每一个都死在同一个地方：找外包，五千起；自己写，不会。想法和实现之间隔着的这条河，叫「工程」。你的备忘录里是不是也躺着几具？

这个项目就是那座桥。它叫 Atoms Native，一道 48 小时笔试题的产物，现在线上就能玩。下面把 48 小时怎么花的、踩了什么坑、我最得意的一个设计，原原本本讲给你。

## 一、题目和我的拆法

最近我在面一个 AI Native 全栈工程师岗，笔试题大意是：48 小时，做一个对标 atoms.dev 的可运行网页应用，用自然语言描述想法，AI 生成能用的应用。交付三样：在线链接、公开源码、说明文档。

我把题目翻译成人话，拆出评审真正想看的四件事：一分钟能玩起来；输入想法真能出活；代码像个正经工程师写的；文档里能看到「人」的取舍。

这四条成了我所有决策的筛子。跟它们无关的，再炫也不做。

## 二、动工前，我先看了别人家的孩子

我把 Bolt.new、Lovable、v0 挨个玩了一遍。好是真的好：Lovable 页面颜值能打，Bolt 连终端都搬进了浏览器，v0 的组件能直接上生产。

但玩多了会发现三件不对劲的事。

第一件，黑盒。提交需求之后屏幕上只有转圈，像等一辆不报站的公交。第二件，假成功。Lovable 一年出过三起安全事故，其中一次泄露 48 天才被发现。对用户来说最吓人的不是失败，是失败还长着成功的脸。第三件，demo 惊艳、production 崩塌。有测评说这些工具在项目复杂到十五六个组件后会集体撞墙，AI 开始亲手弄坏自己刚建的东西。

这一圈玩完我反而踏实了。大厂把「用嘴能造应用」的市场教育做完了，普通人缺的是一个「敢用」的理由。那我就做这个理由。

顺带记两个细节。一是各家入口都极简，打开就一个输入框，我也照做了，官网首页十秒讲清产品，给出演示账号。二是它们免费额度卡得精，Lovable 每天 5 次、v0 每月 50 条，跑到一半没额度最劝退。我的解法土但有效：没有 API Key 也能全流程跑，评审环境不该被 Key 卡脖子。

## 三、四个员工的分工

Atoms Native 的核心设定：在你的浏览器里养一支 AI 开发小队。

Emma 是产品经理，负责把你随口一句「喝水打卡」翻译成机器听得懂的需求规格。没有她，机器听到的就是噪声。Bob 是架构师，画页面骨架，定数据往哪存。Alex 是工程师，真写代码那个，产出完整的单文件 HTML 应用。Mike 是评审员，甲方脾气，看不上就打回，附修改指引。

为什么不是一个 AI 一把梭？你想想，让同一个人既写代码又挑自己的毛病，等于运动员兼裁判。切开之后每个环节都能单独打磨，而且四个角色轮流干活，天然就是一场可视化直播，黑盒问题顺手解了一半。这套流水线就写在 server/agent/pipeline.py 里，包括 Mike 的打回修复环，不是我编的软文。

## 四、真实的 74 秒

你打开 taoxie.vip/atoms-native/studio.html，用演示账号登录（demo / demo123456，免注册）。输入「帮团队管理每日饮水与目标打卡的小工具，带统计图表」，点「⚡ 生成应用」。

接下来 74 秒（真实 DeepSeek 实测均值），活动流滚动：Emma 的需求规格出来，Bob 的数据模型画好，Alex 的代码一段段流出，Mike 挑出问题打回，Alex 修复重交。每一步你全程看得见。

然后预览窗亮了。应用能点、能打卡、数据真能存。桌面、平板、手机三视图切换。不满意就一句话改：「主色调换成绿色」，三十秒出新版，旧版躺在版本历史里随时回滚。满意了导出 HTML，发你妈她都能双击打开。

两个藏在背后的小设计。版本链：每次生成都是一个新版本节点，哪个模型、基于哪版、安全分多少，全部记档；回滚是切指针，旧版本永远完好，像翻相册，不像 Git 那么吓人。Race Mode：几个大模型同题并行竞技（耗时取最大而非求和，实测 48 秒），评审打分排序你挑最好的。一开始我做成串行，A 跑完跑 B，240 秒直接把连接耗死，这是我真实踩的坑。改并行之后的逻辑就是「货比三家」：单次生成质量有波动，那就多要几份，选择权还给你。用户最信任的评审永远是他自己。

## 五、翻车实录：差点骗过我自己的一次「假成功」

这部分我最想写。

某次用一个真实的两三 KB 复杂需求跑生成，DeepSeek 返回了 409 字的「东西」，系统报成功，mock 标记还是 false。我点开一看，那不是代码，是一份被重新格式化的需求文档。我的提示词写「只输出 HTML」，本意是「别解释直接上代码」，模型理解成了「帮这份规格文档只保留 HTML 部分」，人家干得还挺认真。

后背发凉的点在于：我要是没点开看，这次假成功就堂而皇之混过去了。用户以为拿到了应用，其实拿到一份说明书。

于是补了三道防线。提示词重写，规格明确标注「仅作参考」，任务单独强调只输出完整 HTML。产出收敛到统一函数，验证不过带明确指令重试一次，再失败就显式返回。分级降级：首次生成拿不到合法 HTML 才降级离线模板，并诚实打上 mock 标记、明说「本次并非真实生成」；精修和修复环节失败则保留上一版，绝不拿模板货冒充新货。

修完复测：真实生成一万八千多字节，mock 为 false，CI 十二项断言全绿。教训一句话：AI 系统最危险的不是失败，是谎报军情。

## 六、笼子

聊个敏感话题：AI 生成的代码，你敢直接跑吗？我不敢，所以关了笼子。

运行时这层：应用渲染在一个刻意不给 same-origin 权限的 iframe 里，跟你的登录凭证、平台数据物理隔离。有个小机关我挺得意：我在沙箱里注入了一个 localStorage 内存垫片，生成的小应用以为自己在本分存数据，实际全被拦截托管。它用得开心，数据出不了笼子。服务端还有条铁律：永不 eval、exec 用户侧代码。

静态这层：每次生成自动跑一遍对齐 OWASP LLM Top 10 的扫描，注入、密钥泄露、XSS 这些，列明细、给 0 到 100 安全分，分数跟着版本存档。像每次体检报告都归档，翻旧账有据可查。

## 七、摩擦信号：我最偏爱的一个设计

灵感来自 TeamAI 的一个洞察：又长又顺的会话没有记录价值，可一旦你「和 AI 搏斗过」，会话里就藏着值得沉淀的问题。我看到这段的时候真的坐直了。

平移到我的产品里：一次生成顺顺利利跑完，没信息量；但凡出现这些信号，都值得记。LLM 调用失败（权重 30）、输出不合法回退（25）、整轮离线模板（40）、评审打回（12）、用户点踩（25）、用户回滚（15）。加权攒分，过了阈值（40）才提示「这次可能藏着值得记录的问题，建议补进评估集变成永久回归用例」；分数不够，安安静静，绝不打扰。

为什么不做「所有失败都报警」？因为那样就是狼来了，没人看报警了。搏斗过才打扰，本质是用信号密度过滤噪声。更妙的是后半段：线上踩的坑变成明天的回归用例，产品的失败不再蒸发，而是变成它明天更好的理由。代码在 server/friction.py，只观测不阻断，异常全吞，绝不因记录失败搞挂主流程。

## 八、怎么证明它不是花架子

先说研效看板（admin.html）：按「智能体乘模型」统计调用分布与耗时、最近 20 次调用、限流后端自省、24 小时摩擦总览。看不到的指标等于不存在的指标，与其翻日志，不如让数字站到墙上。

然后三板斧。测试打底：30 项单元测试（纯标准库，装都不用装）加 12 项端到端冒烟，覆盖注册、生成、持久化、安全评分、反馈、回滚全链路。CI 看门：每次推送自动跑编译检查、mock 起服、冒烟、评估门禁。企业级自觉：关键动作进带哈希链的审计日志，改一行就能验出来；限流是 Redis 分布式版，挂了自动降进程内、恢复了自动爬回去。

评估门禁值得多说一句。传统软件代码没改行为就不变，AI 产品不是：模型一升级、参数一调，质量会悄悄滑坡。所以我搭了评估集，正常需求加故意挖坑的对抗样本，跑一遍产出硬指标，回归就亮红灯。我还用负例注入做了「门禁自测」，证明坏用例真的会亮灯。你想啊，一个从不报警的门禁，比没有门禁更吓人：你根本不知道它是在保护你，还是陪你睡觉。

## 九、没做的，和这 48 小时怎么花的

克制是这个项目里我最常做的动作：不做支付和企业权限，不做拖拽编辑器（对话式生成已覆盖价值），不接混元千问专属网关（兼容层已预留位置）。

48 小时的花法：头几个小时一行代码没写，拆题、玩竞品、定底线；然后一口气打穿四智能体主链路，先让「一句话进、应用出」真实跑起来，丑一点没关系；主链路通了才做 Race、版本、导出；剩下的时间全砸在真实环境端到端验证，和处理只有真跑才暴露的坑（围栏剥离、串行超时、假成功全是这么抓出来的）。

最大经验一句老话：先让最小的完整闭环跑起来，再谈一切优雅。AI 时代写代码太快，快到「想清楚再做」从美德变成了生存技能，烂方向上跑得越快，返工越多。

## 十、第 8 个点子活过来之后
