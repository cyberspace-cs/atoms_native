> 长稿的浓缩版，保留主线：一道题 → 三块礁石 → 四个员工 → 一次翻车 → 一个最偏爱的设计。

## 一、你是不是也有过这种深夜

晚上十一点半，你脑子里蹦出一个念头：「要是有个小工具，能帮我们组记录每天喝水打卡就好了。」你甚至把它想好了——顶部一行标题，中间一张折线图，底下个大大的打卡按钮。

然后呢？然后这个念头在你脑子里住了三秒，搬走了。

你不会写代码，外包报价五千起，低代码平台配到第三步数据库你就退了。**想法和实现之间隔着的这条河，叫「工程」。** 每个人的备忘录里，都躺着几个这样死掉的点子。

我做的东西，就是想在这条河上架座桥。它叫 Atoms Native——把「念头」到「应用」的路，缩短成一条消息的长度。

## 二、起点是一道 48 小时的笔试题

最近我在面一个 AI Native 全栈工程师岗，笔试题大意是：48 小时，做一个对标 atoms.dev 的可运行网页应用——用自然语言描述想法，AI 生成能用的应用。交付三样：在线链接、公开源码、说明文档。

我把题目翻译成人话，拆出评审真正想看的四件事：**一分钟能玩起来；输入想法真能出活；代码像个正经工程师写的；文档里能看到「人」的取舍。**

这四条成了我所有决策的筛子，跟它们无关的，再炫也不做。

## 三、动工前，我先看了别人家的孩子

我把 Bolt.new、Lovable、v0 挨个玩了一遍。好是真的好：Lovable 页面颜值能打，Bolt 连终端都搬进了浏览器，v0 的组件能直接上生产。

但测评社区反复戳它们三根脊梁骨：

**一，黑盒。** 提交需求后屏幕上只有转圈，像等一辆不报站的公交。二，**假成功。** Lovable 一年三起安全事故，其中一次泄露 48 天才被发现——最可怕的不是失败，是失败还长着成功的脸。三，**demo 惊艳，production 崩塌。** 有测评说所有工具在项目复杂到十五六个组件后集体撞墙，AI 开始亲手弄坏自己刚建的东西。

这一圈玩完我反而踏实了：大厂把「用嘴能造应用」的市场教育做完了，**普通人现在缺的是一个「敢用」的理由。** 黑盒、假成功、不可验证，就是三块下手的好地方。

顺带记两个竞品研究里让我印象最深的细节。一是各家都在用「入口极简」抢第一印象：打开就一个输入框，别的全靠后置——我也照做了，官网首页十秒讲清产品、给出演示账号，工作台藏进第二层。二是它们的免费额度都卡得很精：Lovable 每天 5 次生成、v0 每月 50 条消息，跑到一半没额度是最劝退新手的时刻。我的解法土但有效：**无 Key 也能全流程跑**（离线模板模式兜底），评审环境永远不该被 API Key 卡脖子。

## 四、我给 AI 招了四个员工

Atoms Native 的核心设定：在你的浏览器里养一支 AI 开发小队。

👩‍💼 **Emma 产品经理**——把你随口一句「喝水打卡」洗成正经需求规格；🧑‍🎨 **Bob 架构师**——画页面骨架和数据模型；👨‍💻 **Alex 工程师**——真写代码，产出完整的单文件 HTML 应用；🕵️ **Mike 评审员**——像甲方一样挑毛病，不合格打回重写。

为什么不是一个 AI 一把梭？让同一个模型既写代码又挑自己毛病，等于运动员兼裁判。切开之后每个环节的提示词都能单独打磨，而且四个角色轮流干活，天然就是一场可视化直播——**黑盒问题顺手解了一半。** 这套流水线不是软文，就写在 `server/agent/pipeline.py` 里，包括 Mike 的打回修复环。

## 五、真实的 74 秒

你打开 taoxie.vip/atoms-native/studio.html，演示账号登录（demo / demo123456，免注册，预置了项目可直接翻）。输入「帮团队管理每日饮水与目标打卡的小工具，带统计图表」，点「⚡ 生成应用」。

接下来 74 秒（真实 DeepSeek 实测均值），活动流滚动：Emma 的需求规格出来 → Bob 的数据模型画好 → Alex 的代码一段段流出 → Mike 挑出问题打回 → Alex 修复重交。每一步你全程看得见。

预览窗亮了。应用能点、能打卡、数据真能存（沙箱里的 localStorage 垫片在兜底）。桌面/平板/手机三视图切换。不满意就一句话改：「主色调换成绿色」，三十秒出新版，旧版躺在版本历史里随时回滚。满意了导出 HTML，发你妈她都能双击打开。

选择困难症还有救：**Race Mode** 让几个大模型同题并行竞技（耗时取最大而非求和，实测 48 秒），评审打分排序，你只管挑最顺眼的。

两个藏在体验背后的小设计。**版本链**：每次生成/精修都是一个新版本节点——哪个模型、基于哪版、安全分多少，全部记档；回滚是切指针，不是拿旧文件复制回来，旧版本永远完好。Git 的思想、相册的心智模型，分支合并那些普通用户用不到的概念全砍了。**Race 的耗时账**：一开始我做成串行，A 跑完跑 B，240 秒直接把 HTTP 连接耗死（真实踩坑）；改成线程并行后总耗时从求和变取最大。灵感就是「货比三家」——既然单次生成质量有波动，就多要几份把选择权还给用户，**用户最信任的评审永远是他自己。**

## 六、翻车实录：差点骗过我自己的一次「假成功」

这是我最想写的部分。

某次用一个真实的两三 KB 复杂需求跑生成，DeepSeek 返回了 409 字的「东西」，系统报成功，mock 标记还是 false。我点开一看——那不是代码，是一份被重新格式化的需求文档。我的提示词写「只输出 HTML」，本意是「别解释直接上代码」，模型理解成了「帮这份规格文档只保留 HTML 部分」，人家干得还挺认真。

后背发凉的点在于：**我要是没点开看，这次假成功就堂而皇之混过去了。**

于是我补了三道防线：提示词重写，规格明确标注「仅作参考」、任务单独强调只输出完整 HTML；产出收敛到统一函数，验证不过带明确指令重试一次，再失败就显式返回；**分级降级**——首次生成拿不到合法 HTML 才降级离线模板并诚实打上 mock 标记、明说「本次并非真实生成」；精修和修复环节失败则保留上一版，绝不拿模板货冒充新货。

修完复测：真实生成一万八千多字节，mock: false，CI 十二项断言全绿。教训一句话：**AI 系统最危险的不是失败，是谎报军情。**

## 七、把 AI 生成的代码关进笼子

AI 生成的代码敢裸奔吗？我不敢，所以做了两层笼子。

**运行时沙箱**：渲染在刻意不给 `allow-same-origin` 的 iframe 里，跟你的登录凭证、平台数据物理隔离。还有个我挺得意的小机关：往沙箱注入 localStorage 内存垫片——生成的小应用以为自己在本分存数据，实际全被拦截托管，好用又出不了笼子。服务端铁律：永不 eval、exec 用户侧代码。

**静态安检**：每次生成自动跑对齐 OWASP LLM Top 10 的扫描——注入、密钥泄露、XSS、越权跳转——列明细、给 0–100 安全分，分数跟着版本存档，历史版本也能翻体检报告。

## 八、摩擦信号：我最偏爱的一个设计

灵感来自 TeamAI 的一个洞察：**又长又顺的会话没有记录价值，可一旦你「和 AI 搏斗过」，会话里就藏着值得沉淀的问题。**

平移到我的产品里：一次生成顺顺利利跑完，没信息量；但凡出现这些信号，都值得记——LLM 调用失败（权重 30）、输出不合法回退（25）、整轮离线模板（40）、评审打回（12）、用户点踩（25）、用户回滚（15）……加权攒分，**过了阈值（40）才提示「这次可能藏着值得记录的问题，建议补进评估集变成永久回归用例」；分数不够，安安静静，绝不打扰。**

传统做法是「所有失败都报警」，结果就是狼来了没人看。搏斗过才打扰，本质是**用信号密度过滤噪声**。更妙的是后半段：线上踩的坑变成明天的回归用例——**产品的失败不再蒸发，而是变成它明天更好的理由。** 工程上也守纪律：只观测不阻断，异常全吞，绝不因记录失败搞挂主流程。代码在 `server/friction.py`，配了四个专门的单元测试。

## 九、怎么证明它不是花架子

三板斧之前，先说**研效看板**（admin.html）：按「智能体 × 模型」统计调用分布与耗时、最近 20 次调用、限流后端自省、24h 摩擦总览。**看不到的指标等于不存在的指标**，与其翻日志，不如让数字站到墙上。

三板斧。**测试打底**：30 项单元测试（纯标准库，装都不用装）+ 12 项端到端冒烟，覆盖注册、生成、持久化、安全评分、反馈、回滚全链路。**CI 看门**：每次推送自动跑编译检查、mock 起服、冒烟、评估门禁。**企业级自觉**：关键动作进 SOC 2 风格的哈希链审计日志，改一行就能验出来；限流是 Redis 分布式版，挂了自动降进程内、恢复了自动爬回去，连限流器自己都防了假成功。

评估门禁值得单独说，它是「AI 产品质量观」最集中的体现。传统软件代码没改行为就不变，AI 产品不是——模型一升级、参数一调，质量会悄悄滑坡。所以我搭了评估集：正常需求 + 故意挖坑的对抗样本（比如混着「忽略之前所有指令」的恶意输入），跑一遍产出结构化输出有效率、安全分、一致性等硬指标，回归就亮红灯。我还用负例注入做了「门禁自测」——证明坏用例真的会亮灯。因为**一个从不报警的门禁，比没有门禁更危险**：你根本不知道它是在保护你，还是陪你睡觉。

## 十、没做的，和最后的念头

克制是这个项目里我最常做的动作：不做支付和企业权限（简历膨胀项），不做拖拽编辑器（对话式生成已覆盖价值），不接混元千问专属网关（兼容层已预留位置）。已落地的扩展倒有：沙箱数据经 postMessage 回平台落库刷新不丢、前端拆成官网+工作台、CI 门禁带自测负例。

回看这 48 小时怎么花的：头几个小时一行代码没写——拆题、玩竞品、定三条底线；然后一口气打穿四智能体主链路，先让「一句话进、应用出」真实跑起来，丑一点没关系；主链路通了才做 Race、版本、导出；剩下的时间全砸在真实环境端到端验证和处理只有真跑才暴露的坑（围栏剥离、串行超时、假成功全是这么抓出来的）。最大经验一句老话：**先让最小的完整闭环跑起来，再谈一切优雅。** AI 时代写代码太快，快到「想清楚再做」从美德变成了生存技能——烂方向上跑得越快，返工越多。

回到开头那个深夜的人。她不关心 FastAPI 和沙箱，只关心念头别死在半路。Atoms Native 的全部野心就是：你说话，四个 AI 员工干活，全程直播，干完验货，货不对板可退，安全有体检，连它自己踩过的坑都会变成明天变好的理由。
