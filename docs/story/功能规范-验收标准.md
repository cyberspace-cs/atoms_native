# Atoms Native 功能规范与验收标准（SRS 精简版）
> IEEE 830 风格：每条功能需求唯一编号（FR-xxx），四段式用例（前置条件/主流程/扩展流程/验收标准），非功能需求带数字（NFR-xxx）。
> 定位说明：叙事稿（短/中/长稿）是给人读的故事，本文档是「合同工件」——面试官关心的 communication 桶里，除了 README 可读，还有这条可追溯的规范链。
> 所有条目均对应真实代码，追溯矩阵见文末。

## 1. 引言

- **目的**：明确 Atoms Native 各功能的行为边界与验收方法，作为测试用例与评审验收的依据。
- **范围**：覆盖生成主链路、精修、版本、导出、Race、安全、摩擦信号、看板共 10 项功能需求与 4 项非功能需求。不包含：支付、企业权限、可视化拖拽编辑器（明确 out of scope，见叙事稿「没做什么」章节）。
- **术语**：生成 = 由自然语言想法产出可运行 HTML 应用；精修 = 基于当前版本的对话式增量修改；mock = 无 API Key 时的离线降级模式。

## 2. 功能需求

### FR-001 用户登录
- **前置条件**：系统已部署，用户已打开 studio.html。
- **主流程**：输入用户名密码 → 点击登录 → 服务端校验 → 返回 JWT → 进入工作台。
- **扩展流程**：用户名或密码错误，界面提示错误原因；未注册用户可使用演示账号 demo / demo123456。
- **验收标准**：使用 demo / demo123456 登录，3 秒内进入工作台并展示项目列表；错误密码登录返回明确错误提示而非静默失败。

### FR-002 想法生成应用
- **前置条件**：已登录，处于工作台。
- **主流程**：输入自然语言想法（如「帮团队管理每日饮水打卡」）→ 点击「⚡ 生成应用」→ SSE 活动流实时展示四阶段（产品经理→架构师→工程师→评审）→ 生成完成后预览窗展示可交互应用。
- **扩展流程**：评审打回时活动流展示修改指引与修复版本；模型输出非法 HTML 时自动重试一次，仍失败则按 FR-009 降级。
- **验收标准**：真实模型环境下提交合法想法，60~90 秒内（实测均值 74 秒）产出可点击、可持久化数据的应用；活动流四阶段产出物全部可见。

### FR-003 对话式精修
- **前置条件**：存在至少一个已生成版本。
- **主流程**：在对话框输入修改指令（如「主色调换成绿色」）→ 基于当前版本增量修改 → 产出新版本。
- **扩展流程**：精修失败时保留上一版，绝不以模板货冒充（诚实性约束）。
- **验收标准**：精修指令 60 秒内产出视觉可辨的新版本；精修失败时当前版本保持可用。

### FR-004 版本历史与回滚
- **主流程**：点击「🕘 版本」→ 展示版本链（每节点含：生成模型、时间戳、父版本、安全分）→ 选择历史版本回滚。
- **验收标准**：任意版本可一键回滚；回滚采用指针切换，回滚后旧版本数据完好；版本节点信息与实际相符。

### FR-005 导出单文件应用
- **主流程**：点击「导出」→ 下载自包含 HTML 文件。
- **验收标准**：导出文件双击可在浏览器独立打开并运行，无需平台环境。

### FR-006 多模型并行竞技（Race Mode）
- **主流程**：点击并行生成 → 多个模型线程并行同题生成 → 评审逐一打分排序 → 用户选择最优版本。
- **约束**：并行执行，总耗时取最慢模型而非求和（串行实现曾致 240 秒超时，已修复）。
- **验收标准**：实测总耗时 48 秒左右；产出多份带评分排序的候选。

### FR-007 安全扫描与评分
- **主流程**：每次生成完成自动触发扫描（对齐 OWASP LLM Top 10：提示注入、密钥泄露、XSS、越权跳转等）→ 输出问题明细与 0~100 安全分。
- **验收标准**：安全分随版本存档，历史版本可回查；对含注入样本的输入能检出并扣分。

### FR-008 摩擦信号与沉淀建议
- **主流程**：生成过程中自动采集摩擦事件（LLM 调用失败 W30、输出回退 W25、整轮模板 W40、评审打回 W12、修复失败 W15、点踩 W25、回滚 W15）→ 加权聚合 → 超阈值（40）时提示沉淀为回归用例。
- **约束**：只观测不阻断，模块异常一律吞掉，绝不影响主流程。
- **验收标准**：低于阈值的会话不产生任何打扰；达阈值出具体建议；人为注入观测异常时主流程不受影响（对应单元测试 TestFriction）。

### FR-009 离线降级（诚实性）
- **主流程**：无 API Key 或首次生成均失败时 → 使用离线模板 → 界面明确标注 mock「本次并非真实生成」。
- **约束**：仅首次生成允许降级；精修与修复环节失败保留上一版。
- **验收标准**：无 Key 环境全流程可跑通；mock 标记在界面与数据中一致且可核验。

### FR-010 研效看板
- **主流程**：打开 admin.html → 展示智能体×模型调用分布、平均耗时、最近 20 次调用、限流后端自省、24 小时摩擦总览。
- **验收标准**：数据来自 /api/metrics 实时接口；限流后端模式（Redis/降级）如实展示。

## 3. 非功能需求

- **NFR-001（性能）**：真实模型生成端到端耗时 60~90 秒（实测均值 74 秒，DeepSeek）；API 限流：默认窗口内按用户限流，Redis 故障自动降级进程内令牌桶，恢复后自动回切。
- **NFR-002（安全）**：生成应用运行于无 allow-same-origin 的沙箱 iframe；服务端永不 eval/exec 用户侧生成代码；关键操作（登录、生成、回滚、反馈）记入带哈希链的审计日志，篡改可被校验发现。
- **NFR-003（可用性/环境）**：无 API Key 环境全流程可运行（mock 模式）；评审 clone 后零构建即可启动。
- **NFR-004（可验证性）**：30 项单元测试（纯 Python 标准库）+ 12 项端到端冒烟测试，CI（GitHub Actions）每次推送自动执行，含评估门禁与门禁自测（负例注入证明红灯会亮）。
